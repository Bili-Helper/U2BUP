# v0.8.1 工作流模块：上传后清理本地视频

日期：2026-10-23。状态：**实现预览 `0.8.1-preview.2`，完整 v0.8.1 验收尚未完成**。下文保留完整目标设计；目前实现范围见本节。

### 当前实现范围

- Windows 手动清理闭环：工作流内置模块及「本地视频清理」页签，已索引素材批选、路径筛选、精确保留项、人工上传确认、冻结预览、永久删除、CSV/JSON 清单导出和历史记录。
- YouTube 核验模式：新上传锁定文件并保存身份凭据；只有同一文件的完整上传记录才能用于自动核验，检查当前频道及平台处理成功，apply 前再次查询。旧记录、合并/分片来源的覆盖关系无法证明时保留并提示人工确认，不自动降级。
- 专用认证接口：`GET/POST /api/workflows/cleanup`、`POST /api/workflows/cleanup/{id}/apply`。普通图预览只提示人工复核，不产生删除 Intent；`local.video.delete` 尚未开放。
- 删除通过 Windows 文件句柄执行；锁定祖先目录和目标文件，拒绝 reparse point、硬链接、越界、非视频文件、文件变更及只读库。存在未结束媒体/上传任务时整批阻断。
- 逐项日志在删除前持久化，已完成项不重放；失败/冲突项重新预览。中断项标为待核对。清理摘要进入任务中心；元数据另行存档，旧库重扫保留已清理记录，注册库标记 `local_deleted`。
- 验证：70 项 Rust、32 项前端测试；120 视频批量测试、平台响应模拟、真实 HTTP/临时目录测试及桌面/手机浏览器流程通过；提供 Windows 便携预览包。
- 待交付：来源分片覆盖自动判定、多目标结构化证据、未索引目录直接选择、跨平台删除与其验收。本版人工确认说明可填写在线地址，尚无逐视频在线地址编辑器。

当前实现不是完整 v0.8.1 稳定版；不会仅凭上传任务 `completed` 自动认定为可清理。

## 1. 用户需求与本次用例

用户已确认视频上传到在线平台，希望删除本地视频释放空间，同时保留弹幕、直播间信息、字幕及其他元数据。该能力作为独立 Workflow module，可手动批量运行，也可在未来上传工作流的确认步骤之后复用。

2026-10-23 的实际用例：选择 LiveRec 目录，用户确认除一个显式排除的 MP4 外，其余视频均已上传。实际删除 120 个 FLV，文件逻辑大小合计 `176468021416` 字节（约 164.35 GiB）；保留 1 个 MP4、1081 个 XML、877 个 TXT、2 个 JSON、55 个 PS1。保留文件的路径、大小和修改时间均经核对。本次上传完成依据是**用户确认**，没有查询平台来验证。

这次生成的 `LiveRec-video-deletion-manifest.csv` 仅记录删除目标的路径、大小和修改时间，是本机操作清单，已通过根 `.gitignore` 排除。它不是平台上传凭据，也不是未来执行器可直接信任的删除指令；实际文件名、主播目录和远端私有信息无需写入公共示例。

## 2. 模块定位与 v0.8.1 范围

| 项目 | 规划约定 |
| --- | --- |
| 显示名称 | 上传后清理本地视频 |
| 内置 ID / 短名 | `com.u2bup.builtin.cleanup-local-video` / `cleanup-local-video` |
| 分组 | 发布与归档 |
| 输入 | 已选本地素材或目录内的视频候选、上传确认证据、排除项 |
| 输出 | 清理预览、冻结计划、逐文件执行结果、删除清单、更新后的本地保留状态 |
| 执行边界 | 预览模块为纯函数；扫描、证据查询、计划冻结及删除由 Rust 宿主负责 |
| 拟新增宿主 Intent | `local.video.delete`，仅内置模块可提出，宿主重新验证 |
| 默认行为 | 不自动删除；用户审阅冻结清单后明确执行永久删除 |

v0.8.1 交付手动触发的完整闭环，支持在 U2BUP 之外完成上传的历史文件。上传确认证据采用平台无关结构；首版可接现有 YouTube 上传记录和人工确认，其他平台通过人工确认使用。录制结束自动清理、无人值守自动删除策略、其他平台自动核验、远端视频删除和从云端恢复文件不属于本版。

## 3. 工作流与交互

```text
选择素材 / 目录 → 收集上传确认证据 → 设置保留例外
    → 清理预览 → 冻结清单 → 用户执行永久删除 → 逐项回执与元数据核验
```

1. **选择范围**：从素材库批选栏或工作流画布进入；显示素材库及目录。目录选择先由宿主枚举为固定候选集，不能在执行时重新递归扩张范围。未索引的视频先登记必要的素材身份及旁文件关联。
2. **确认上传**：对候选文件逐项或批量填写确认证据；显示“平台已核验”与“用户已确认”两种来源。批量人工确认绑定本次明确列出的文件集合，不能永久标记整个文件夹为“以后均可删除”。
3. **设置例外**：支持按素材 ID 或素材库内精确相对路径添加保留项，以及在预览中取消单项。排除优先于上传确认和其他规则；排除文件仍出现在结果中并显示原因。v0.8.1 不需要通配符排除。
4. **预览**：逐项展示文件路径、大小、目标平台、已知远端地址、确认来源与时间、可删除/排除/待确认/阻断原因。汇总视频数量、预计回收字节、保留旁文件数量。目录中文件名相同的条目也可区分。
5. **执行**：用户执行的是已经冻结的清单；明确显示“永久删除本地视频，保留弹幕和元数据”。默认不移入同盘回收站，以满足释放空间的目标；不能承诺撤销或从在线平台恢复原片。
6. **查看结果**：任务中心展示逐文件成功、跳过、冲突、失败与待核实；可导出 CSV/JSON，并仅重试符合条件的失败项。汇总区区分计划字节、成功删除文件的逻辑字节和可测得的磁盘可用空间变化，后者可能受其他写入、硬链接或快照影响。

## 4. “确认已上传”的判定

| 证据来源 | 删除前条件 | 不足时的行为 |
| --- | --- | --- |
| 本应用上传 + 平台核验 | 上传任务、素材/成品身份、目标账号和远端视频 ID 对应；宿主确认远端处理成功且可访问 | 处理中、失败、无权限、账号不符、远端不存在或状态未知均阻断 |
| 用户人工确认 | 用户对冻结文件集合确认已上传并已核对在线版本；记录平台、确认时间、说明，支持填写视频 URL/ID | 未确认项保留；没有 URL 时允许人工确认，但标为“用户已确认，未自动核验” |

- 当前 `youtube.rs` 的 `UploadJob.status = completed` 表示上传响应已取得视频 ID，提示仍可能在处理。**不能仅凭 completed、上传字节达到 100%、相同标题或一个布尔字段删除文件。** 平台处理状态核验需单独实现。
- 人工确认适用于外部平台、历史上传及没有本应用上传记录的文件；不能把人工确认显示成 API 验证成功。若切换为人工确认，须记录新的确认证据，不能在平台核验失败后自动降级。
- 私密或未列出的视频可以是有效在线副本，是否公开不作为删除条件。平台核验使用对应授权账号，不以匿名访问失败直接认定上传失败。
- 拆分、合并后的来源关系必须证明所删视频内容的完整覆盖。一个分片上传成功不能推导整段原片可删除；仅有 `source_ids` 也不足以证明覆盖。无法证明时阻断自动判定，允许用户另行明确确认完整覆盖。
- 多平台场景在计划中明确本次要求保有的目标集合，所有必需目标均满足条件后才可删除；不强制用户未选择的平台必须上传。

## 5. 文件保留与宿主校验规则

1. **仅删除明确列入清单的视频文件**：首版视频扩展名白名单对齐现有媒体入口 `mp4/mov/mkv/flv/webm/ts`，大小写不敏感；未知类型保留并提示。文件体积不作为判定“可删”的依据。
2. **保留全部其他文件和目录**：包括 XML、TXT、JSON、ASS、SRT、VTT、封面、图片、脚本及未知旁文件，不要求与视频同名，也不因文件较大而删除。不删除目录、不清空文件夹、不连带清理数据库、历史任务或成品记录。
3. **路径限定**：宿主根据素材库及素材身份解析路径；规范化后校验路径组件边界，拒绝越界、只读库及文件/祖先目录上的符号链接、Windows junction/reparse point。不能只做字符串前缀判断，也不能信任前端传入的绝对路径。
4. **身份与稳定性**：冻结记录文件大小、修改时间、文件身份及必要的内容校验信息；删除前再次核对。当前 `AssetV2.content_hash` 仅基于首 1 MiB 和大小，不能当成完整内容一致的证明。换盘、根目录重绑定、同路径替换、文件增长或预览后变更使该项失效。
5. **并发**：录制、合并、切割、上传、选帧等仍依赖该文件的活动任务阻断清理；宿主持有按文件身份的清理锁，再检查依赖和文件状态，协调新任务启动。路径检查与删除之间应通过平台支持的句柄/目录约束防止替换竞态，无法保证时保守阻断。
6. **最终复核**：平台核验模式在 apply 时重新查询必需远端目标；人工确认模式重新校验冻结证据与文件身份。排除清单始终优先。执行期间新出现的视频不能加入本次计划。
7. **只移除文件内容的本地副本**：成品指向原文件的直传项、跨记录共享路径和硬链接需识别并去重；所有受影响记录与必需目标均满足条件才删除，不能因某一条记录已上传忽略另一个活动任务。

## 6. 数据、Intent 与恢复设计

以下为拟定协议，不是当前 API。实现时沿用工作流草稿、冻结 run 和任务中心；是否扩展现有冻结端点或增加专用端点在编码时决定，不能让通用元数据 apply 静默获得删除权限。

| 对象 | 必要内容 |
| --- | --- |
| 上传确认证据 | `id`、素材/成品及文件快照、必需目标平台/账号/视频 ID 或 URL、`method = platform_verified / user_confirmed`、确认时间与说明、覆盖关系 |
| 清理计划 | `id`、模块及规则版本、素材库及根目录身份、冻结时间、明确文件集合、排除集合、保留旁文件快照、预计字节 |
| `local.video.delete` | `planId`、`itemId`、`libraryId`、`assetId`、证据 ID；真实删除路径和许可由宿主冻结记录解析，不能携带任意 shell 或可信路径指令 |
| 逐项日志 | 原路径、文件身份、大小与修改时间、关联远端目标、确认来源、执行时间、删除前/后状态、原因及错误 |
| 本地保留状态 | 新增 `local_deleted`（拟定值）及 `cleanupRunId/deletedAt`；与普通 `missing`、素材盘离线及远端发布状态分开保存 |

执行顺序：先持久化完整清单与逐项准备记录，再逐文件核验和删除，随后持久化结果；日志无法写入时不开始删除。状态至少区分 `planned / deleting / deleted / excluded / blocked / conflict / failed / needs_review`。

若删除已发生但回执落盘前崩溃，恢复时保留待核实状态并对照准备记录；仅发现文件不存在不能伪称本次删除成功或重复计入释放字节。同路径出现的新文件必须保留并重新预览；重试已完成项是无操作。失败不撤销此前已经完成的删除。

删除后保留素材标题、主播/房间、录制时间、技术信息、弹幕关联、发布记录、远端链接及清理日志。素材库显示“本地视频已清理”，支持查看元数据及已记录的在线地址；本地播放、选帧和重新上传显示文件不可用。重扫不得抹掉清理状态或相关记录；以后恢复本地文件须重新核验身份后关联。

运行清单保存在应用本地数据目录，导出文件由用户选择位置；不将用户路径或私有在线地址写入仓库。仓库根只需精确忽略本次 `LiveRec-video-deletion-manifest.csv`，不泛化忽略全部 CSV。

## 7. 实施拆分与依赖

- [ ] 素材状态与迁移：保留仅有旁文件的历史素材，兼容旧 LiveRec 与 `assets_v2`，关联直传/合并成品和远端记录。
- [ ] 上传证据：平台无关数据结构、批量人工确认、YouTube 宿主核验及完整覆盖判定。
- [ ] 宿主清理：候选发现、冻结计划、精确排除、路径/身份/活动任务校验、持久执行日志、逐项恢复。
- [ ] Workflow：注册内置模块，扩展宿主 Intent 白名单和专用执行校验；第三方 L1 包不能发起文件删除，预览仍不执行文件 I/O。
- [ ] UI：素材库入口、模块配置、证据与例外编辑、预览/执行、任务结果、元数据保留状态和导出清单。
- [ ] 验收：前端预览测试、Rust 临时目录文件测试、持久化恢复测试、隔离实例 UI 验收。

依赖 v0.8.0 的稳定素材身份、素材库根目录与旧索引兼容；不能为了清理先丢失原素材或旁文件关系。测试使用临时目录和伪造平台响应，不删除真实 LiveRec 文件，也不依赖真实上传即可回归。

## 8. v0.8.1 验收条件

| 场景 | 必须满足的结果 |
| --- | --- |
| 本次用例回归 | 临时目录模拟 120 个 FLV、1 个保留 MP4 和各类旁文件；仅删除确认的 120 项，MP4 与全部旁文件路径、字节内容和修改时间不变 |
| 外部平台历史上传 | 无 U2BUP 上传记录时可批量人工确认；无 URL 的项仍可按人工模式运行，确认范围和来源可追溯 |
| 未确认 / 处理未完成 | 未上传、仅上传完成但仍处理、平台核验失败、覆盖不完整或结果未知的项均不会被自动判为可删除 |
| 精确排除 | 排除优先；中文、空格、大小写、同名不同目录、原始文件与成品均按身份/精确路径区分 |
| 保留元数据 | 包含未关联、不同名、大体积、未知扩展名旁文件及子目录；所有非目标内容保持不变 |
| 冻结范围 | 冻结后新增文件不会被删除；修改排除项或选择范围须重新冻结，旧计划不能冒用新确认 |
| 越界与竞态 | `..`、相邻前缀目录、链接/junction、只读库、根目录更换、文件替换/增长均被阻断；同路径新文件不被旧任务删除 |
| 活动任务与共享文件 | 正在录制/处理/上传或存在其他依赖时保留；重复资产/共享路径不重复删除或重复统计 |
| 多片段 / 多目标 | 单分片完成不能清理完整源片；全部必需目标确认后才可执行，不擅自增加平台条件 |
| 故障与恢复 | 权限拒绝、锁定文件、日志写入失败及中途崩溃逐项可追溯；已删项不重放，不把外部缺失计为本任务成果 |
| 重扫与重启 | 素材、弹幕、在线链接、上传历史和清理记录仍可查看；`local_deleted` 与普通缺失、离线区别显示 |
| 模块边界 | 前端预览零文件删除；未知 Intent、伪造路径/证据、禁用模块、未确认计划或第三方模块请求均不能触发删除 |
| 发布证据 | 在各宣称支持的平台验证路径及删除行为；记录测试、UI 验收与版本构建结果后，才将本模块标为已实现 |
