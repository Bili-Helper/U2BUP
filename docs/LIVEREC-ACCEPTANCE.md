## A. 扫描与归档

1. 全量导入 88 目录、163 视频；XML/TXT 单独存在也可查询，不判为可直接删除的垃圾。
2. 重扫不重复入库；文件移动、大小变化、缺失分别显示，不依赖文件名作为唯一 ID。
3. 23186926、24337682、27308354 的多个别名目录聚合展示，保留原路径。
4. FLV 与历史 .flv.mp4 区分来源角色；来源未知的成品不能默认再并入原片。
5. 读取 XML 原始标题、分区、房间 ID 与带时区时间；界面可查看来源与冲突。
6. 在线抓取当前房间真实 ID/短号、主播资料、标题/状态并缓存；超时、风控、已失效房间不阻断本地操作。实际抓取成功和失败都要有可见结果。
7. 在线当前信息不覆盖历史场次信息；无网络时使用本地历史资料。

## B. 计划与时间

1. 跨午夜连续片段属于同场，按直播源时区显示，不受 Windows 本地时区影响。
2. 同日同标题但超过间隔阈值的两场不会撞名。
3. _PART000 等录制器后缀不改变规范化标题，原值仍可追溯。
4. 横→竖→横默认形成三个连续兼容段；按画幅归集合并必须显式选择。
5. 相同比例但分辨率/音轨/编码/SAR 不同的素材禁止直接混拼。
6. 重叠片段、重复候选、标题变化、缺失时长和无法解析的文件名都可查看原因和人工处理。
7. 合并预览列出每个输入、顺序、输出名、预计时长/大小、拆分原因、占用空间；修改规则后计划可复现。

## C. YouTube 上限

实际库存已知时长的 162 个文件中没有 >12h 单文件，另有 1 个时长未知。需用合成媒体与规划器数据覆盖边界，不能以真实库存未发现该情况为由省略；未知时长必须检测后才能进入自动合并计划。

1. 输入总和超过目标时长或体积时自动分组；输出硬性不得超过平台最大限制。
2. 单个输入超长必须真正切割，不能生成仍然超长的单元素组。
3. 关键帧对齐引起成品超出计划时触发再拆分，不能只看请求的 -t 值。
4. _partN 再合并也执行相同限制检查。
5. 体积边界用字节测试，避免 GB/GiB 混用；封装开销预估有余量，成品重新读取实际大小。

## D. 执行与恢复

1. 首先在测试输出根目录处理一组体积小的真实片段，再测跨午夜/画幅变化等代表案例；全库批量合并不是首个 smoke test。
2. 源文件不修改。执行前发现源文件变化或仍在增长时停止该计划。
3. 中文、空格、单引号、方括号等路径正常工作；执行参数不经 shell 解释。
4. 已有同名但来源未知/损坏的输出不能当作成功，也不能被静默覆盖。
5. FFmpeg 退出 0 后仍检查音视频流、实际时长、限制、抽样解码和片段连接处；记录验证等级。
6. 中途取消或杀进程后，原片完好、临时文件不成为正式成品；重启可重试任务且不重复登记。
7. 同计划重复提交不重复执行；规则变化生成新版本。
8. 空间不足、并发任务空间竞争、FFmpeg 缺失/版本异常都有可操作错误信息。
9. 输出保存源片段时间映射，供未来字幕、弹幕和切片使用。

## E. UI 与平台

1. WebUI 与桌面查看同一素材、计划和任务状态；重启持久存在。
2. 搜索、日期/房间/画幅筛选、范围选择与“全选筛选结果”正确，不把当前页当全部。
3. 批量命名预览支持普通规则，提示碰撞与不匹配；文件名与显示名、远端标题分开。
4. 原始 FLV 在 WebView 无法直接解码时可生成预览代理或使用受支持播放器，不能仅显示播放按钮。
5. 桌面构建与 API 测试在本机实际运行；跨平台支持须对应平台 CI/运行证据。
6. 干净测试环境能使用包内 FFmpeg/FFprobe，证明未意外依赖本机 PATH。

M1 完成意味着真实素材管理与合并闭环可用，不意味着 YouTube 上传、多平台实时录制及 AI 已完成。
