# 已上传视频与素材库的批处理管线设计

本文根据 2026-09-22 的授权频道只读研究制定产品方向。数据来源是应用私有目录 `app/.local/channel-research/` 下的 `REPORT.md`、`summary.json`、`pattern-summary.json` 和视频快照；这里只保留聚合数字与匿名结构，不复制真实标题、名称、房间号或视频 ID。

下文的模块和契约是设计目标，不等于全部已经实现。首批实现及验证结果由集成人员在文末登记。模块接口、Google API 对照与第三方开发说明见 [WORKFLOW-MODULE-API.md](WORKFLOW-MODULE-API.md)。

## 1. 真实问题与优先级

统计以 **1,034 个唯一 video ID** 为口径。同步曾返回 1,887 行，853 行是同 ID 的额外返回记录，不能计为重复上传；采集范围也尚未与 Studio 账号总数对账。

| 观察 | 产品含义 |
| --- | --- |
| 公开 603、私密 350、不公开 81 | 筛选和差异预览必须展示可见性；修改命名不应隐含改变发布状态。 |
| 916 个标题含日期，43 个含多个日期 | 需要独立的录制时间/场次模型，不能依赖上传列表排序。 |
| 424 个标题含技术文本，133 个含下划线，131 个以哈希结尾 | 先解析再格式化，技术信息保留在资料中；不能全局替换后丢失信息。 |
| 282 条有房间号候选，涉及 43 个值；667 条有名称候选，涉及 110 个字符串 | 建立来源身份与别名台账；名称字符串数量不是已验证主播数量。 |
| 3 个房间候选对应多个名称候选 | 冲突处理和一次确认、后续复用，比单纯关键词归类更重要。 |
| 918 条描述为空，1,034 条标签为空，应用分组均为空 | 描述模板、标签规则和动态分组有直接价值。 |
| 快照中 1,034 条 `hasCustomThumbnail=false` | 提供待封面队列和关联素材取帧；该字段不是封面质量评分。 |
| 110 组同来源同日期候选涉及 315 条视频 | 需要场次/版本对照，不能直接判重。 |
| 19 条时长不超过 10 秒；唯一同标题组内两条分别为 3 秒和 3 小时 12 分 44 秒 | 极短中断、补档和同名版本进入核验队列，不自动删除。 |
| 568 条含地区限制；567 条 blocked、1 条 allowed | 做目标地区可播放性检查，与版权记录分开。 |
| 350 条缺标题语言，959 条缺音频语言；只有 1 条字幕字段为 true | 将语言建议、字幕资产与章节作为后续独立模块。 |
| 总时长约 2,367 小时，中位数约 2 小时 4 分钟；21 条 sd，1 条禁止嵌入 | 长视频章节、素材对账、发布设置例外值得独立管理。 |

优先次序：**P0 可组合规则与差异预览 → P1 经审阅的远端执行及素材关联 → P2 内容理解、字幕章节与效果分析**。优先级表示建议顺序，不代表交付承诺或已实现状态。

## 2. 统一资产模型

来源身份、录制场次、素材、成品和云端视频使用不同实体，避免“一个文件就是一个视频”的限制。

```text
来源身份（平台 + 房间号/已验证 UID，名称及别名）
  └─ 录制场次（起止时间、时区、原直播主题、证据）
       ├─ 源素材（多个录制文件、中断与续录）
       └─ 成品版本（合并/切片/横屏/竖屏/修复版）
            ├─ 本地媒体、封面、字幕与章节
            └─ 云端发布记录（频道 + YouTube ID + 发布/修改历史）
```

同一成品允许关联多个发布记录，同一场次允许多个成品；源素材与成品之间保留加工关系。平台未确认时使用未知值，房间号不当作主播 UID。播放列表绑定确认过的来源身份和实际列表 ID，名称变化只更新显示名。

每个推断字段保存 `value / state / evidence / rule / confidence`。状态至少区分“候选、已确认、有冲突”；置信度是可解释的规则结果，不冒充统计概率。人工确认和覆写不能被下一次自动解析静默覆盖。原始元信息与规范资料分开保存，YouTube `publishedAt` 与录制发生时间分开保存。

统一对账视图输出“已关联、候选关联、未上传、云端存在但本地未找到”。只有已确认关系可以自动继承主播、场次与封面来源；相似标题和接近时长仅提供候选证据。

## 4. Canvas/Dify 式编排与节点契约

工作台由模块库、可平移缩放的画布、节点配置、批次预览和运行结果组成。节点可拖动排布、连接、启停、复制、删除，管线可保存和再次使用。**画布位置只决定布局，连线决定数据流和执行顺序**；配置变化后旧预览应标为过期。

节点定义建议采用以下契约，字段名属于设计示意，具体代码以实现为准：

| 契约项 | 内容 |
| --- | --- |
| 标识与版本 | 节点实例 ID、模块类型、模块版本、配置版本、启用状态、画布位置。 |
| 输入/输出端口 | 资产批次、规范资料、修改建议、媒体引用、复核结果；声明接受的类型。 |
| 依赖与能力 | 所需字段及本地媒体/远端读取/远端写入/AI 能力；依赖不足返回具体原因。 |
| 运行结果 | 处理数量、命中、跳过、需复核、失败，以及逐资产输出。 |
| 字段修改 | 原值、新值、字段路径、理由、规则、证据、候选状态；未变化不产生写入。 |
| 副作用声明 | 纯计算、本地保存或远端操作；预览只计算，不执行远端副作用。 |
| 可追踪信息 | 输入快照版本、模板版本、节点执行顺序与时间、错误来源；不记录凭据。 |

首批宜覆盖单一数据流的连接、排序与配置；条件分支、分支合流、可复用子管线可以分阶段扩展。未支持的结构需要明确提示，不能绘制了分支却仍悄悄按数组顺序执行。循环连接、端口不兼容、上游缺失、多个节点冲突修改同字段，应在预览前反馈。

两个建议预设：

```text
历史整理：频道选择 → 历史解析 → 来源映射 → 分类标签 → 标题描述
          → 播放列表计划 → 地区/例外检查 → 差异审阅 → 输出

待上传：素材选择 → 来源/场次关联 → 分类标签 → 标题描述
        → 封面候选 → 上传设置审阅 → 上传 → 列表/封面后续任务
```

远端执行阶段需保存独立操作结果。上传已成功而归列表失败时，只续做归列表；未知结果要先核对远端状态。保存执行记录本身不等于已实现幂等，只有实际验证过对应操作链路后才能声称可以安全重试。

## 5. 解析与远端执行边界

历史标题中的日期须验证日历有效性、数字边界和时间范围。多日期可能表示跨天或合并场次，缺少时区时保持待确认。`rN_M` 的真实语义未核实，应保留原文；不能自动解释为分 P 或画幅。技术词可能是主题的一部分，只按明确位置与已知模式提出清理建议。

YouTube 的 `publishedAt` 是发布相关时间，不能当录制时间；`regionRestriction` 说明地区可见性；`licensedContent` 也不是“无版权问题”的布尔结论。本批快照没有获取完整版权申诉、警告原因或盈利数据。上述字段语义见官方 [Video resource](https://developers.google.com/youtube/v3/docs/videos)。

版权管理 API 与普通频道元信息能力不同。官方 [Content ID API 说明](https://developers.google.com/youtube/partner) 描述的是内容合作伙伴的权利管理能力，并要求相应的 Content Manager 账户。因此当前产品应提供人工记录、处理进度和 Studio 跳转，并将自动获取申诉详情作为单独的连接器能力检测；不能向所有频道显示“已自动扫描版权警告”。

远端元信息写入必须先读取当前值，合并已审阅字段，再构造请求。YouTube `videos.update` 会覆盖指定 `part` 的可写字段，遗漏已有值可能清除内容；修改 snippet 还必须提供 title 和 categoryId。预览后发生的远端变化需要重新核对，不能覆盖用户在 Studio 的新编辑。规则依据见官方 [videos.update](https://developers.google.com/youtube/v3/docs/videos/update)。

标题、描述和标签在提交前校验平台长度与内容约束；本地自定义类别与 YouTube `categoryId` 分开映射。语言字段是否可写以实际 API 能力核验为准，尤其不能只因读取到 `defaultAudioLanguage` 就假定当前更新接口支持它。

当前帧取封面分为“媒体取帧”和“设置远端图片”两步。官方 [thumbnails.set](https://developers.google.com/youtube/v3/docs/thumbnails/set) 接收图片内容，并可能因账户权限或速率限制失败；保存截图不能直接算设置成功。每种远端操作应显示能力/授权缺口、成功数与失败原因，额度和重试参数由实际 API 响应与已验证执行机制决定。

官方资料核验日期：2026-09-22。

## 6. 后续统一管理模块

| 模块 | 与当前样本的联系 | 完成条件 |
| --- | --- | --- |
| 场次与版本归档 | 同来源同日期候选多，存在跨日期与合并线索 | 可比较源素材、加工成品和云端视频，确认横竖屏/切片/补档关系，保留加工历史。 |
| 语言与本地化 | 标题语言与音频语言缺失口径不同 | 分别确认文字/音轨语言；翻译标题描述保持原义，并单独保存本地化版本。 |
| 字幕资料库 | 字幕字段仅 1 条为 true，但未读取字幕正文 | 导入/生成字幕候选，校验时间轴和对应成品版本；字幕发布作为独立能力。 |
| 章节生成 | 样本主要为长录像，人工定位成本高 | 从场次、字幕或人工标记生成章节候选，验证时间顺序、时长范围和版本一致性后进入描述预览。 |
| 素材完整性检查 | 极短中断、SD 和多版本需要对照 | 本地探测时长/分辨率/音轨等信息，指出缺失与差异；黑屏/静音识别另有可解释检测结果。 |
| 重复与补档对账 | 标题相同不代表内容相同 | 元信息只生成候选；具备本地文件时可增加指纹证据，任何清理动作独立审阅。 |
| 发布设置模板 | 公开/私密/不公开混合，存在禁止嵌入例外 | 模板显式包含目标设置；与命名管线分开选择，保存修改前状态及执行结果。 |
| 变更历史与回退计划 | 批改可能同时涉及多个资源 | 记录字段快照、具体请求结果与操作者；回退生成新的差异计划，不声称能撤销所有平台行为。 |
| 内容效果复盘 | 当前只有播放/点赞/评论基础统计 | 接入额外授权的分析数据后再比较标题/封面效果；不从零播放或标签数量推导因果。 |

## 7. 首批切片与验收

首批切片目标是让真实频道缓存与本地素材进入同一个可配置流程，完成“选对象 → 拼模块 → 配规则 → 预览具体差异 → 保存结果”。优先落地解析、分类、标题描述、列表规划、例外检查和人工复核；封面、版权与 AI 节点可先提供诚实的计划/记录/接口边界。远端批改只有在对应后端、授权和逐条结果处理接通后才登记为可用。

最低验收覆盖：保存后重载保持模块配置和布局；执行顺序受实际连线/已声明顺序控制；已上传和待上传使用一致资料规则；日期与身份冲突不被无条件确认；非空描述不被默认覆盖；预览不会写远端；不支持的能力明确显示；私有调研文件不进入版本库。
